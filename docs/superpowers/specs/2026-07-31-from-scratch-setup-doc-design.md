# 「從零建置」文件設計（2026-07-31）

## 背景

使用者問：專案一開始要下哪些指令才能建出基礎專案、要裝哪些套件？這在課綱裡嗎？

查證結果：**不在。** `LEARNING.md` 的 Ch0 有八節（核心概念、決策取捨、踩到的坑、換機接續、指令速查、檔案地圖、閱讀動線、作業），全部假設專案已存在。最接近的「換機接續」第一行是 `git pull`，那是拉既有 repo，不是從零建立。

也就是說，這個專案怎麼從空資料夾長出來的，只存在於對話裡 —— 這正好違反 `LEARNING.md` 自己寫的原則：「一章的決策如果只存在於對話裡，換機就等於沒發生過。」

## 需求

使用者要的用途有兩個，優先序如列：

1. **自己實際重建一次**（主要）—— 需要可照做的逐步教學，每步附預期輸出
2. **未來開新專案時當模板**（次要）—— 需要區分「通用」與「本專案特有」

## 決策

### 1. 獨立文件，不動 `LEARNING.md`

`docs/從零建置.md`。使用者明確要求不要再往 `LEARNING.md` 塞內容。

**取捨：** 也考慮過寫進 Ch0 一節（維持「唯一進度來源」原則），以及寫兩份（docs 放通用、LEARNING 放專案版）。前者會把可複用模板埋進一份近 400 行的學習歷程；後者要維護兩份同樣的內容，遲早失同步。獨立單檔同時服務兩種用途。

### 2. 三階段結構，每階段有驗證點

```text
階段 1 產生骨架          → pnpm start:dev 看到 Hello World!
階段 2 接上 Prisma 與資料庫 → prisma validate + generate 成功
階段 3 寫 Ch0 程式碼      → GET /health 回 200、test:e2e 綠燈
```

「跑完應該看到什麼」是「可照做」與「只是清單」的分界。

### 3. 用 🔧 標記本專案特有的選擇

無標記＝任何 NestJS + Prisma 7 專案都要做；🔧＝可換（pnpm、Neon、PORT=3100、skills 鏡像整理）。這是同時滿足用途 1 與 2 的關鍵。

### 4. 階段 3 不重貼程式碼

改成「照 `src/main.ts` 開頭的閱讀動線把檔案抄一遍」。那些檔案已有 `[教學]` 註解，貼第二份會造成日後改一邊、另一邊失同步。

### 5. 全部指令實跑驗證，不憑記憶

在暫存資料夾實跑 `@nestjs/cli@11 new` 與 `prisma@7 init`，比對產物與本專案的實際差異。

**驗證推翻了三個原本要寫進文件的說法：**

- `tsconfig.json` 以為要手動開 `emitDecoratorMetadata` —— 實際上 `nest new` 預設就有，本專案完全沒改過這個檔案
- 以為 TypeScript 需要手動降到 5.9 —— 實際上 scaffold 給的就是 `^5.7.3`，`LEARNING.md` 說的「從 7 降版」是當初額外裝 TS 7 造成的，回到預設即可
- 以為 `tsx` 是 Prisma CLI 讀 `prisma.config.ts` 的必要條件 —— 實測不裝也能讀，屬選用

同時發現 `.agents/skills/`、`.claude/skills/`、`.windsurf/skills/`、`skills-lock.json` 是 `prisma init` 產生的，不是誰手動加的。

## 內容範圍

**寫入：** scaffold 指令與產物、完整套件清單（每個註明為什麼要裝）、Neon 開庫與 `.env`、**scaffold 之後必須手動改的六處設定**（附 diff 與不改會看到的錯誤訊息）、最終驗證、`nest new` 預設 vs 本專案的完整差異表。

**不寫：** 程式碼本體、Neon 註冊的圖文步驟（會過期，連官網）、Ch2 才出現的 `.env.test` 用法。

**核心訊息：** `nest new` + `prisma init` 只能做到約 70%，剩下 30% 是接線，而且那 30% 的錯誤訊息都很難從字面推回原因。

## 驗收

- 指令與產出已在 2026-07-31 實跑驗證
- 六處手動調整的 diff 逐一比對過 scaffold 與本專案的實際檔案
- 階段 3 的結果由現有 `pnpm test:e2e` 保證
