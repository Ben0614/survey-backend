# 從零建置這個專案

這份文件記錄「一個空資料夾 → `GET /health` 回 200」的完整過程。

**兩種讀法：**

- **想親手重建一次** —— 從頭照做。每一步都附「跑完應該看到什麼」，對不上就是出問題了。
- **以後開新的 NestJS + Prisma 專案** —— 直接抄，把標了 🔧 的地方換成你自己的選擇。

**標記約定：**

| 標記 | 意思 |
| --- | --- |
| （無標記） | 任何 NestJS + Prisma 7 專案都要做 |
| 🔧 | 本專案的選擇，換成別的做法也行 |

> 文件裡的指令與產出都在 2026-07-31 實際跑過驗證，不是憑記憶寫的。

---

## 前置需求

- **Node.js** —— 本專案用的 `@types/node` 是 `^24`，Node 20 以上都可以。
- **pnpm** 🔧 —— 換 npm / yarn 也行，只是後面每個指令要跟著換。沒裝的話：`npm install -g pnpm`。

## 階段 1：產生 NestJS 骨架

### 1-1 執行 scaffold

```bash
pnpm dlx @nestjs/cli@11 new survey-backend
```

`pnpm dlx` 的意思是「臨時下載這個工具並執行，不裝到專案裡」——類似前端的 `npx`。過程中會問你要用哪個套件管理器，選 **pnpm** 🔧。

**產生的東西：**

```text
survey-backend/
├── src/
│   ├── main.ts                 進入點
│   ├── app.module.ts           根 module
│   ├── app.controller.ts       範例 controller（等一下會刪）
│   ├── app.service.ts          範例 service（等一下會刪）
│   └── app.controller.spec.ts  範例單元測試（等一下會刪）
├── test/
│   ├── app.e2e-spec.ts         範例 E2E 測試（等一下會刪）
│   └── jest-e2e.json
├── package.json                含 build / start:dev / test 等 scripts 與 jest 設定
├── tsconfig.json               已經開好 emitDecoratorMetadata（NestJS 的必要條件）
├── tsconfig.build.json
├── eslint.config.mjs
├── .prettierrc
├── .gitignore
└── nest-cli.json
```

**這一步已經幫你做掉的事**（所以不用自己設定）：TypeScript、ESLint、Prettier、Jest、`emitDecoratorMetadata`、以及 `package.json` 裡那整組 scripts。這就是 `nest new` 相當於前端 `create vite` 的部分。

### 1-2 驗證

```bash
cd survey-backend
pnpm start:dev
```

瀏覽器開 `http://localhost:3000`，應該看到 **Hello World!**。

看到了就代表骨架沒問題。按 Ctrl+C 停掉，繼續下一階段。

## 階段 2：接上 Prisma 與資料庫

### 2-1 安裝套件

```bash
# 執行期用的（會被打包進正式環境）
pnpm add @nestjs/config @prisma/client @prisma/adapter-pg pg

# 只有開發／建置時用的
pnpm add -D prisma @types/pg dotenv
```

每個套件的用途：

| 套件 | 為什麼需要 |
| --- | --- |
| `@nestjs/config` | 讀 `.env`。NestJS 沒有內建這件事 |
| `@prisma/client` | 執行期的查詢 client |
| `@prisma/adapter-pg` | **Prisma 7 才需要**。v7 起 Prisma 不自己連資料庫，改用 Node 的 pg 驅動，這個套件是兩者之間的轉接頭 |
| `pg` | 真正負責連 PostgreSQL 的驅動 |
| `prisma` | CLI 工具（`migrate`、`generate`、`studio`） |
| `@types/pg` | `pg` 的 TypeScript 型別 |
| `dotenv` | 給 `prisma.config.ts` 用。CLI 是獨立 process，沒有 NestJS 的 ConfigModule 幫忙讀 `.env` |

> **這裡就是 v6 與 v7 最大的差別。** 如果你在網路上看到的教學只裝 `@prisma/client` 和 `prisma`，那是 v5/v6 的寫法，在 v7 會失敗。

### 2-2 初始化 Prisma

```bash
pnpm exec prisma init --datasource-provider postgresql
```

**產生的東西：**

```text
prisma/schema.prisma   資料模型定義（目前只有兩塊設定，沒有 model）
prisma.config.ts       Prisma CLI 的設定檔
.env                   含一行範例用的 DATABASE_URL
.gitignore             確保 .env 與產生的 client 不進版控
.agents/skills/        ← Prisma 官方的 AI 技能包（正本）
.claude/skills/        ← 上面那份的鏡像
.windsurf/skills/      ← 上面那份的鏡像
skills-lock.json       技能包的版本鎖定
```

> 最後四項是 Prisma 7 附帶的功能，讓 AI 工具查得到**正確版本**的 Prisma 用法。這在 v7 特別有價值 —— 網路上多數教學是 v5/v6，AI 若只憑訓練資料回答很容易給錯。

### 2-3 建立資料庫並填連線字串

🔧 本專案用 **Neon**（雲端 Postgres，有免費方案）。換成本機 Postgres 或 Docker 都可以，只要最後能拿到一條連線字串。

1. 到 [neon.com](https://neon.com) 註冊並建立一個 project
2. 在 Connection Details 複製連線字串
3. 貼進 `.env`，並把 `prisma init` 產生的那行範例刪掉

```bash
# .env
PORT=3100                        # 🔧 本專案避開 3000，因為前端 Nuxt 要用
DATABASE_URL="postgresql://<user>:<password>@<host>/<database>?sslmode=verify-full&channel_binding=require"
```

同時建立 `.env.example` 進版控，只放 key 的形狀、不放真實密碼：

```bash
# .env.example
PORT=3100
DATABASE_URL="postgresql://<user>:<password>@<host>/<database>?sslmode=verify-full&channel_binding=require"
```

### 2-4 六處必要的手動調整

**這是整份文件最重要的一節。** `nest new` + `prisma init` 只能做到約 70%，剩下的接線得自己來 —— 而且不做的話，錯誤訊息都很難從字面推回原因。

#### ① `prisma/schema.prisma` —— 改 client 輸出位置與模組格式

```diff
 generator client {
   provider = "prisma-client"
-  output   = "../generated/prisma"
+  output   = "../src/generated/prisma"
+  moduleFormat = "cjs"
 }
```

- **`output` 改到 `src/` 底下**：TypeScript 的 `rootDir` 是「所有輸入檔的共同祖先」自動推導的。放在專案根目錄的 `generated/` 會把 `rootDir` 從 `src/` 撐大到根目錄，編譯輸出就變成 `dist/src/main.js`，`pnpm start:prod` 直接找不到進入點。
- **`moduleFormat = "cjs"`**：產生器預設輸出 ESM（用到 `import.meta.url`），而 NestJS 編譯成 CommonJS。不加這行會在執行期看到 `ReferenceError: exports is not defined`。

#### ② `.gitignore` —— 跟著改路徑

`prisma init` 寫進去的是 `/generated/prisma`，但我們把輸出改到 `src/` 了：

```diff
-/generated/prisma
+/src/generated
+.env.test
+
+# 🔧 skills 正本放 .agents/，.claude 與 .windsurf 底下只是指向它的
+# junction，內含絕對路徑（換機或專案改名就會斷），屬於本機產物。
+.claude/settings.local.json
+.claude/skills/
+.windsurf/skills/
```

（`.env.test` 是 Ch2 才會建立的測試資料庫設定，先加進來免得日後忘記。）

🔧 最後三行是本專案為了在兩台電腦間輪流開發做的整理 —— 把 `prisma init` 產生的三份 skills 收斂成「`.agents/` 是正本，另外兩份用連結指過去」。單機開發的話不必這樣做。

#### ③ `tsconfig.build.json` —— 排除根目錄的 `.ts` 檔

```diff
-"exclude": ["node_modules", "test", "dist", "**/*spec.ts"]
+"exclude": ["node_modules", "test", "dist", "**/*spec.ts", "prisma.config.ts"]
```

理由同 ①：`prisma.config.ts` 在專案根目錄，不排除的話 `rootDir` 一樣會被撐大。

> **以後在專案根目錄新增任何 `.ts` 檔都要記得加進這裡。**

#### ④ `package.json` 的 `jest` 區塊

```diff
   "jest": {
     "moduleFileExtensions": ["js", "json", "ts"],
     "rootDir": "src",
     "testRegex": ".*\\.spec\\.ts$",
     "transform": { "^.+\\.(t|j)s$": "ts-jest" },
+    "moduleNameMapper": { "^(\\.{1,2}/.*)\\.js$": "$1" },
-    "collectCoverageFrom": ["**/*.(t|j)s"],
+    "collectCoverageFrom": ["**/*.(t|j)s", "!generated/**"],
     ...
```

`moduleNameMapper` 是把 `import ... from './client.js'` 的 `.js` 拿掉，讓 Jest 找得到真正的 `.ts`。

（誰在寫 `.js`？**是 Prisma 產的程式碼，不是你。** `src/generated/` 底下的檔案互相 import 時帶著 `.js`（例如 `client.ts` 裡的 `from "./enums.js"`），因為那份產物要同時能被 ESM 專案使用。**你自己寫的 import 一律不帶副檔名** —— 這個專案是 CJS，副檔名可省，也是 NestJS 的預設寫法。）

#### ⑤ `package.json` 的測試 scripts

```diff
-"test": "jest",
-"test:watch": "jest --watch",
-"test:cov": "jest --coverage",
-"test:e2e": "jest --config ./test/jest-e2e.json"
+"test": "node --experimental-vm-modules node_modules/jest/bin/jest.js --passWithNoTests",
+"test:watch": "node --experimental-vm-modules node_modules/jest/bin/jest.js --watch --passWithNoTests",
+"test:cov": "node --experimental-vm-modules node_modules/jest/bin/jest.js --coverage --passWithNoTests",
+"test:e2e": "node --experimental-vm-modules node_modules/jest/bin/jest.js --config ./test/jest-e2e.json"
```

Prisma 7 的查詢編譯器是 WASM，載入時用動態 `import()`，Jest 預設沙箱不支援。這個 Node 旗標沒辦法透過 `jest` 指令傳進去，只能直接呼叫 Jest 的進入點。

不改的話會看到：`A dynamic import callback was invoked without --experimental-vm-modules`。

> **日後新增任何測試腳本都要保留這段前綴。**

#### ⑥ `test/jest-e2e.json` 與 `eslint.config.mjs`

```diff
   "transform": { "^.+\\.(t|j)s$": "ts-jest" },
+  "moduleNameMapper": { "^(\\.{1,2}/.*)\\.js$": "$1" }
```

E2E 有自己一份 jest 設定，跟 ④ 是兩份獨立的檔案，**改一份不會影響另一份**。

```diff
-ignores: ['eslint.config.mjs'],
+ignores: ['eslint.config.mjs', 'dist/**', 'src/generated/**'],
```

Prisma 產生的程式碼不是我們寫的，不該被 lint。

### 2-5 驗證

```bash
pnpm exec prisma validate    # 應顯示 "The schema at prisma\schema.prisma is valid 🚀"
pnpm exec prisma generate    # 應在 src/generated/prisma/ 產生一堆 .ts
ls src/generated/prisma      # 應看到 client.ts、models.ts、enums.ts 等
```

三個都過就代表 Prisma 接好了。

## 階段 3：寫 Ch0 的程式碼

### 3-1 刪掉 scaffold 的範例檔

```bash
rm src/app.controller.ts src/app.service.ts src/app.controller.spec.ts test/app.e2e-spec.ts
```

刪完 `src/app.module.ts` 會因為 import 不到而壞掉 —— 下一步就會重寫它。

### 3-2 建立這六個檔案

程式碼**不在這份文件裡**，因為它們已經在專案裡、而且每個檔案都有 `[教學]` 註解。從 `src/main.ts` 開始，照每個檔案開頭的「下一站」逐一抄過去：

| 順序 | 檔案 | 職責 |
| --- | --- | --- |
| 1 | `src/main.ts` | 進入點：組裝 → 掛 shutdown hooks → listen |
| 2 | `src/app.module.ts` | 根 module，改成 import ConfigModule / PrismaModule / HealthModule |
| 3 | `src/prisma/prisma.service.ts` | 把 PrismaClient 包成可注入的零件 |
| 4 | `src/prisma/prisma.module.ts` | `@Global()`，全應用共用一個連線池 |
| 5 | `src/health/health.controller.ts` | `GET /health` |
| 6 | `src/health/health.module.ts` | 註冊上面那個 controller |
| 7 | `test/health.e2e-spec.ts` | 自動驗證整條路 |

🔧 順帶一提，`src/health/` 這種「一個資料夾裝一個功能」的結構是慣例，不是強制。`nest g resource <名稱>` 可以自動產生這組檔案，Ch2 開始會用到。

### 3-3 最終驗證

```bash
pnpm start:dev
```

另開一個終端機（或用 `api.http` 的 Send Request）：

```bash
curl http://localhost:3100/health
```

應該得到：

```json
{ "status": "ok", "database": "connected", "timestamp": "2026-07-31T..." }
```

最後跑測試：

```bash
pnpm test:e2e     # 應該 1 passed
pnpm build        # 應該產生 dist/main.js（不是 dist/src/main.js）
```

全綠就完成了。

## 附錄：`nest new` 預設 vs 本專案的完整差異

如果你只想快速知道「到底改了哪些」，這張表就是全部：

| 檔案 | 改動 |
| --- | --- |
| `package.json` dependencies | 加 `@nestjs/config`、`@prisma/client`、`@prisma/adapter-pg`、`pg` |
| `package.json` devDependencies | 加 `prisma`、`@types/pg`、`dotenv` |
| `package.json` scripts | 四個 test 指令改用 `node --experimental-vm-modules ...` |
| `package.json` jest | 加 `moduleNameMapper`；`collectCoverageFrom` 加 `!generated/**` |
| `tsconfig.json` | **完全沒改**（`emitDecoratorMetadata` 本來就是預設） |
| `tsconfig.build.json` | `exclude` 加 `prisma.config.ts` |
| `test/jest-e2e.json` | 加 `moduleNameMapper` |
| `eslint.config.mjs` | `ignores` 加 `dist/**`、`src/generated/**` |
| `.gitignore` | `/generated/prisma` 改為 `/src/generated`；加 `.env.test` |
| `prisma/schema.prisma` | `output` 改到 `src/`；加 `moduleFormat = "cjs"` |
| `prisma.config.ts` | 沒改（`prisma init` 產生的原樣） |
| `src/` | 刪掉三個範例檔，改寫 `app.module.ts`，新增 `prisma/` 與 `health/` |
| `test/` | 刪掉 `app.e2e-spec.ts`，新增 `health.e2e-spec.ts` |

### 兩個常見誤解

**「TypeScript 是不是要降版？」** 不用。`nest new` 給的就是 `^5.7.3`，本專案沒有動過。`docs/chapters/ch00-環境建置.md` 提到的「從 7 降到 5.9」是當初額外裝了 TypeScript 7 才出的問題，回到 scaffold 預設就沒事了。

**「`tsx` 這個套件做什麼的？」** 專案的 devDependencies 裡有它，但實測 Prisma CLI 不需要它就能讀 `prisma.config.ts`。它應該是早期嘗試時裝的，可以視為選用 —— 新專案不必跟著裝。
